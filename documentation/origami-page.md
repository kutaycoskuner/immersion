# Origami page

The origami page (`/origami/<model>`): a flat sheet folded into a finished piece, step by step. The models are JSON files; the bundled ones have their own links, and any model file can be dropped on the page.

| Link | Model |
| --- | --- |
| [/origami/dodecahedron](https://kutaycoskuner.github.io/immersion/origami/dodecahedron) | 12 pentagons, 11 folds, 3 steps (also plain `/origami`) |
| [/origami/cube](https://kutaycoskuner.github.io/immersion/origami/cube) | 6 squares, 5 folds, 2 steps |

## Use

- **step bar** (bottom centre), one step at a time:
    - **▶ step** plays the next step and stops there (at the end it starts over from the flat sheet)
    - **0 1 2 3** jump to a step: 0 is the flat sheet, the last the finished piece (their tooltips name the step)
    - the bar has a tick at every step and snaps onto a step when it comes close, so a step is reached exactly
    - the text shows the current step and its label
- **models** (top left): the bundled models as links
- **drop a model file** (`.json`) anywhere on the page: it is checked and shown instead; a broken file lists every problem it has
- **toolbar** (bottom left): face names, Blender-style random colours; the back of the sheet (the outside of a folded solid) is a darker shade of its face's colour, so a wall seen from outside reads as a wall
- camera: drag to orbit, wheel to zoom, right drag to pan, the [viewport gizmo](viewport-gizmo.md); the camera frames each model flat and folded, which is also the reset view

## The model file

`"format": "immersion-fold"`, `"version": 1`, JSON. Examples: `static/origami/cube.json`, `static/origami/dodecahedron.json` (served next to the pages, e.g. `/origami/cube.json`).

```json
{
	"format": "immersion-fold",
	"version": 1,
	"name": "cube",
	"unit": "edge length 1",
	"points": { "p0": [0, 0], "p1": [1, 0], "p2": [1, 1], "p3": [0, 1], "p4": [0, -1], "p5": [1, -1] },
	"faces": {
		"bottom": { "points": ["p0", "p1", "p2", "p3"], "base": true },
		"front": { "points": ["p4", "p5", "p1", "p0"] }
	},
	"folds": [
		{ "id": "fold-front", "line": ["p0", "p1"], "fixed": "bottom", "moving": "front",
		  "direction": "valley", "angle": 90, "step": 1, "type": "hinge" }
	],
	"steps": [{ "step": 1, "label": "raise the sides" }]
}
```

- **`points`**: the flat sheet, named 2D points `[x, y]`
- **`faces`**: polygons, their corners **counter-clockwise** seen from the front of the sheet (that defines the front); exactly one face is the `base`, which stays on the ground
- **`folds`**: one per face that turns
    - `line`: two points, an edge shared by `fixed` and `moving`; it is the fold axis
    - `fixed`: the face that stays; `moving`: the face that turns, with everything folded onto it
    - `direction`: `valley` turns the moving face up, towards the front of the sheet; `mountain` away from it
    - `angle`: how far it turns, in degrees: 0 flat, 180 folded flat onto `fixed`; the angle between the faces afterwards is 180 minus this (cube 90; dodecahedron 63.43, its faces then meet at 116.57)
    - `step`: from 1; folds of one step move together, the steps one after another
    - `type`: `hinge` (rigid faces on a shared edge, for solids); `flat` (180-degree folds through every layer, for paper planes) is in the format but not built yet
- **`steps`** (optional): a label per step
- in 3D the sheet lies on the ground, its front facing up: `(x, y)` becomes `(x, 0, -y)`; each fold line's position in 3D follows from the folds before it, so the file never needs 3D coordinates

### What the loader checks

Every problem is listed (the page shows them), nothing throws:

- format and version, a name
- every point is `[x, y]` with two numbers; every face has 3 or more known points, counter-clockwise
- exactly one base face
- every fold: a supported type, a line of two known points that is an edge of both its faces, valley or mountain, an angle from 0 to 180, a whole step from 1
- the folds form a tree from the base: every other face turns on exactly one fold and is connected to the base

## How it folds

The faces hang in frames, a hinge tree like the unfolding cube's (`cubeNet.ts`), but read from the file: each face's frame turns about its fold line inside its fixed face's frame. At the bar's value T, a fold of step k is at `T - (k - 1)` of its angle (eased, between 0 and 1).

## The dodecahedron's net

- two "flowers": the base with its five petals, and the lid with four petals; a bridge face joins them
- step 1: the five petals rise around the base (a bowl); step 2: the four petals around the lid; step 3: the bridge and the lid swing over and close the solid
- the file was generated by mirroring pentagons across their edges and choosing a join where the flat net has no overlapping faces and the folded faces land on 12 different places
- `foldModel.spec.ts` checks: 20 corners all equally far from the centre (the cube: 8), **every face on its own place** (20 corners alone can be fooled: two faces on one spot still leave every corner there, which is how a first version shipped with two faces doubled and two places open), and no face passing through another at any stage

## Files

| File | What it does |
| --- | --- |
| `src/routes/(app)/origami/[[model]]/+page.svelte` | the page: model links, toolbar, step bar, play, drag and drop, problem list |
| `src/routes/(app)/origami/[[model]]/+page.ts` | the model from the address, the list of pages to prerender |
| `src/lib/components/OrigamiScene.svelte` | the viewport: builds and frames a model, folds it to the bar's value |
| `src/lib/origami/foldFormat.ts` | the file format (types) and its loader with the checks |
| `src/lib/origami/foldModel.ts` | builds the hinge tree in three.js, `setProgress` |
| `src/lib/origami/models.ts` | the bundled models (every `static/origami/*.json`) |
| `static/origami/*.json` | the bundled models |

Tests: `foldModel.spec.ts` (both models load, lie flat at 0, close when finished with every face on its own place, are not closed half way, fold without faces passing through each other -- the collision check is tested itself; a broken file lists its problems; `flat` is named as not supported yet).

## Adding a model

1. write `static/origami/<id>.json` (or drop it on the page first to see the problems)
2. it appears in the list and gets its link `/origami/<id>`; add it to `ORDER` in `models.ts` to move it up the list
3. add it to the tests in `foldModel.spec.ts` with its number of corners (closing, every face on its own place, no collisions)
